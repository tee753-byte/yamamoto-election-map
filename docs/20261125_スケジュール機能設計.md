# スケジュール機能 設計記録

## 目的

少人数の幹部・運営メンバーが、予定と日付単位の参加可能時間を安全に共有する。
一般公開、一般利用者の登録、外部カレンダー同期は行わない。

## データ構造

### `schedule_events`

予定名、開始・終了日、開始・終了時刻、終日、時間未定、時刻補足、カテゴリ、
ステータス、場所、担当者・役割、詳細、要確認事項、各種URLを保存する。

- 日付は `date`、時刻は `time` で保存し、タイムゾーン変換による日付ずれを防ぐ。
- `version` を更新ごとに増やし、古い画面からの上書きを拒否する。
- 登録者、最終更新者、登録日時、更新日時を記録する。
- 中止は削除せず `cancelled` として残せる。

### `schedule_availability`

利用者と日付の組み合わせごとに、参加可能・参加不可・未定、終日、時間帯、備考を保存する。
予定とは関連付けないため、同じ日に複数予定があっても一度の入力で済み、予定がない日にも登録できる。

## 権限

- 有効なログイン利用者だけが予定と参加可能情報を閲覧できる。
- 管理者と作業担当者は予定を登録・編集できる。
- 作業担当者は自分が登録した予定だけを削除でき、管理者はすべて削除できる。
- 各メンバーは自分の参加可能情報だけを更新でき、管理者は代理登録できる。
- 閲覧のみの利用者は更新できない。
- UIだけでなく、Server Action、サービス、Supabase RPC・RLSでも権限を確認する。

## 画面

- `/schedule` に予定一覧、月間カレンダー、参加可能日の3表示を設ける。
- スマートフォンでは予定一覧を初期表示とする。
- ホームには直近3件と、4つ目の機能カードを表示する。
- 参加可能時間はメンバー色のチップで表示し、タップすると備考と更新者を確認できる。

1. 本番Supabaseのpublicスキーマとデータをローカルへバックアップした。
2. `20261125000100_schedule.sql` を本番へ適用した。
3. `20261125000200_schedule_initial_events.sql` で初期予定10件を登録した。
4. RLSとRPC権限の統合テストを実行した。
5. アプリをVercelへデプロイした。
6. マイグレーション履歴、登録件数、公開ログイン画面を確認した。

`supabase/seed.sql` の予定候補はローカル表示確認専用であり、本番には投入しない。
